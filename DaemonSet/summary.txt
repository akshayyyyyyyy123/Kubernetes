(*) What problem does DaemonSet solve?
  - Imagine you have 5 Kubernetes nodes: Node-1, Node-2, Node-3, Node-4, Node-5
  - You have a requirement: "I need one log-collector Pod running on every node."
  - If you use a normal Deployment: replicas: 5 ..., you get 5 Pods, but Kubernetes doesn't guarantee one Pod per node.
  
  - You could end up with:
        Node-1 → Pod
        Node-2 → Pod
        Node-3 → Pod
        Node-4 → Pod
        Node-5 → Pod
        
  - but you could also get:
       Node-1 → Pod Pod
       Node-2 → Pod
       Node-3 → Pod Pod
       Node-4 → Pod
       Node-5 → ❌

  - That's not what you want. 

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

  (*) DaemonSet
    - A DaemonSet ensures that a copy of a Pod runs on each eligible node in the cluster.

              DaemonSet
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
    Node-1      Node-2      Node-3
       ↓          ↓          ↓
     Pod         Pod         Pod


   - If a new node joins:
           Node-4 joins
                ↓
        DaemonSet detects it
                ↓
        Creates Pod on Node-4


  - If a node is removed:
          Node-3 removed
              ↓
        Its DaemonSet Pod disappears with it

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

(*) The key difference

  - Deployment: "I want N replicas of my application."

                Deployment
                    ↓
                3 replicas
                    ↓
                Pod Pod Pod


  - DaemonSet: "I want one copy on every eligible node."

                DaemonSet
                   ↓
                Node-1 → Pod
                Node-2 → Pod
                Node-3 → Pod
                Node-4 → Pod

(*) Where do we use DaemonSets?

  - Very commonly for node-level agents:
        📝 Log collection — Fluent Bit
        📊 Monitoring agents — Datadog
        🔐 Security agents
        🌐 Networking agents
        📈 Node metrics collectors
        
  - For example:
        Node-1 → Fluent Bit
        Node-2 → Fluent Bit
        Node-3 → Fluent Bit
        Node-4 → Fluent Bit

  - Each Fluent Bit Pod collects logs from its own node.

🔥 Interview definition

A DaemonSet is a Kubernetes workload controller that ensures a copy of a Pod runs on every eligible node. When a new eligible node joins the cluster, the DaemonSet 
automatically creates a Pod on it. It is commonly used for node-level agents such as logging, monitoring, and security agents.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

(*) Why is it useful?

- DaemonSets are mainly used for node-level agents.

- Examples:
    Logging       → Fluent Bit
    Monitoring    → Datadog Agent
    Security      → Security Agent
    Networking    → Network Agent
    
- Example:  
    Node-1 → Fluent Bit
    Node-2 → Fluent Bit
    Node-3 → Fluent Bit
Each agent can collect information/logs from its own node.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

(*) Does it really run on every node?

- Not necessarily. Every eligible node. 
- You can control eligibility using:
    * nodeSelector
    * Node Affinity
    * Taints & Tolerations

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

(*) DaemonSet + Taints

- Suppose:
      Node-3
      role=database
      taint: role=database:NoSchedule

- DaemonSet Pod without toleration: ❌ Can't run on Node-3

- Add matching toleration:
      tolerations:
      - key: role
        operator: Equal
        value: database
        effect: NoSchedule
- Now: ✅ DaemonSet Pod is allowed on Node-3
