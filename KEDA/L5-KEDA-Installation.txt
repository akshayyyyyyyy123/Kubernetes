  - Before installing anything, let's verify the tools on your Mac. Helm is a package manager that simplifies installing Kubernetes applications such as KEDA.
  - Run the following commands:

What we expect:
  * helm version returns a version if Helm is installed
  * minikube status shows the cluster components running

STEP 02 — Add KEDA

  - First, one important concept: KEDA runs inside your Kubernetes cluster. Its operator watches KEDA resources such as ScaledObject and coordinates event-driven
autoscaling.


2.1 - Add the KEDA Helm repository
- We tell Helm, "KEDA's installation package is available from this location. Register it so I can use it."
- This command does not install KEDA or create pods.

COMMAND
    # helm repo add kedacore https://kedacore.github.io/charts
OUTPUT
    "kedacore" has been added to your repositories

- To verify the registered repository:
COMMAND
    # helm repo list
OUTPUT
    NAME    	URL
    kedacore	https://kedacore.github.io/charts


2.2 — Update the Helm repository
- Helm checks the registered repositories and refreshes its local chart information.
- Imagine KEDA publishes a new chart version. Your local Helm cache might not know about it yet. Updating the repository refreshes that information.

COMMAND
    # helm repo update
OUTPUT
    Hang tight while we grab the latest from your chart repositories...
    ...Successfully got an update from the "kedacore" chart repository
    Update Complete. ⎈Happy Helming!⎈


- To see the KEDA chart versions Helm knows about:

What these options mean:
  - keda — the Helm release name.
  - kedacore/keda — the official KEDA chart.
  - --namespace keda — installs KEDA into its own namespace.
  - --create-namespace — creates that namespace if it doesn't exist.

STEP 04 — Verify the installation

A. Check the pods
  - What it does: Lists the pods in the keda namespace.
  - Depending on the chart version and configuration, you'll typically see pods for components such as:
    * keda-operator — watches KEDA resources and coordinates scaling
    * keda-operator-metrics-apiserver — exposes external metrics to Kubernetes
    * keda-admission-webhooks — validates KEDA resource configurations

# kubectl get pods -n keda
NAME                                               READY   STATUS    RESTARTS        AGE
keda-admission-webhooks-7dbfdf4d44-pxbnm           1/1     Running   0               12m
keda-operator-7b8cf9b678-85wzx                     1/1     Running   0               12m
keda-operator-metrics-apiserver-7b8d7dd476-q6zx8   1/1     Running   0               12m



B. Check the deployments
  - You should see KEDA components such as the operator, metrics server, and possibly the admission webhooks, depending on the chart version and configuration.
# kubectl get deployments -n keda
NAME                              READY   UP-TO-DATE   AVAILABLE   AGE
keda-admission-webhooks           1/1     1            1           16m
keda-operator                     1/1     1            1           16m
keda-operator-metrics-apiserver   1/1     1            1           16m



C. Check the Helm release
  - Lists Helm releases installed in the keda namespace.
# helm list -n keda

keda	  keda     	    1       	2026-10-24 19:53:47.923456 +0530 IST	         deployed	    keda-2.21.0	         2.21.0



D. Check KEDA's CRDs
  - Lists KEDA-related Custom Resource Definitions.
  - CRDs extend Kubernetes' API with new resource types. KEDA uses them to introduce resources such as:
      * ScaledObject
      * ScaledJob
      * TriggerAuthentication
  - Once the relevant CRDs are installed, Kubernetes can recognize those custom resource types.

STEP 05 — Understand what you have installed

|-----------------------|-------------------------------------------------------------------------------------|
|    Component          |             	          Purpose                                                     |
|-----------------------|-------------------------------------------------------------------------------------|
|  KEDA Operator	      |       Watches scaling configuration and coordinates scaling actions                 |
|  Metrics API Server	  |       Makes supported external metrics available to Kubernetes' autoscaling system  |
|  Admission Webhooks	  |       Validate KEDA configurations                                                  |
|      CRDs	            |       Allow Kubernetes to recognize KEDA-specific resource types                    |
|  keda namespace	      |       Keeps KEDA's namespaced resources organized                                   |
|  Helm release	        |       Tracks the installation for future management                                 |
--------------------------------------------------------------------------------------------------------------|

SUMMARY OF COMMANDS

# 1. Verify the cluster
minikube status
kubectl get nodes

# 2. Verify Helm
helm version

# 3. Register the KEDA chart repository
helm repo add kedacore https://kedacore.github.io/charts

# 4. Refresh chart metadata
helm repo update

# 5. Check available KEDA chart versions
helm search repo kedacore/keda --versions

# 6. Install KEDA
helm install keda kedacore/keda \
  --namespace keda \
  --create-namespace

# 7. Verify the installation
kubectl get pods -n keda
kubectl get deployments -n keda
helm list -n keda
kubectl get crds | grep keda.sh
