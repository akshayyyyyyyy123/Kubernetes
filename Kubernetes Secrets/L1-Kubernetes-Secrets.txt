🔐 Kubernetes Secrets 🔐

What is a Secret?

- A Secret is a Kubernetes object used to store and provide sensitive information such as passwords, API tokens, SSH keys and TLS certificates to Pods.
- Examples:
      DB_PASSWORD
      API_TOKEN
      AWS credentials
      TLS certificates
      SSH keys
- The main difference from ConfigMap:
    ConfigMap  → non-sensitive configuration
    Secret     → sensitive configuration

----------------------------------------------------------------------------------------------------------------------------------------------------------

Why do we need Secrets?
- Suppose your application needs a database password.

❌ Bad approach
Put it directly in your Pod YAML:

env:
  - name: DB_PASSWORD
    value: "MySuperPassword123"

- Now the password is sitting directly in your Kubernetes manifest. You don't want that.

✅ Better approach
Store it in a Secret:

                    Secret
                      │
                      │ DB_PASSWORD
                      ↓
                     Pod
                      │
                      ↓
                   Container
                      │
                      ↓
                  DB_PASSWORD

- The application gets the password without the password being directly embedded in the Pod definition.

----------------------------------------------------------------------------------------------------------------------------------------------------------

Basic Secret

apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
data:
  DB_PASSWORD: bXlQYXNzd29yZA==

----------------------------------------------------------------------------------------------------------------------------------------------------------

#### Base64 Encoding and Decoding ####

# echo -n "myPassword" | base64
bXlQYXNzd29yZA==

# echo -n "bXlQYXNzd29yZA==" | base64 --decode
myPassword

----------------------------------------------------------------------------------------------------------------------------------------------------------

⚠️ Very important interview point

- Base64 ≠ encryption
- Base64 is simply encoding.
- So don't say: "Kubernetes Secrets encrypt passwords using Base64." That's incorrect.

----------------------------------------------------------------------------------------------------------------------------------------------------------

Opaque in Kubernetes Secrets

- Opaque is the default secret type in Kubernetes. It means the Secret contains arbitrary key-value data, with no special built-in meaning assigned to 
those keys.
- Kubernetes basically says, "I'll store these secret values and make them available to your Pod, but I don't assign special meaning to what the 
keys represent."
- One important point: Opaque does NOT mean encrypted. Secret values in a manifest's data: field are Base64-encoded, which is encoding rather than encryption.
- Opaque = generic secret type. You can define your own key-value pairs, using either data (Base64) or stringData (plain text).


(*) data: → Base64-encoded value

data:
  DB_USERNAME: YWRtaW4=
  DB_PASSWORD: cGFzc3dvcmQ=

echo -n "YWRtaW4=" | base64 --decode
admin

echo -n "cGFzc3dvcmQ=" | base64 --decode
password

---------------------------------------------

(*) stringData: → Plain-text value

  stringData:
    DB_PASSWORD: password

- Kubernetes will convert stringData into the Secret's stored representation.
