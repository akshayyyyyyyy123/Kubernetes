How does a Pod consume a Secret?
- Just like ConfigMaps, there are three common ways:
    1. Individual environment variable
    2. envFrom
    3. Volume

---------------------------------------------------------------------------------------------------------------------------------------------------------

1. Individual environment variable
  - One specific Secret key → environment variable.

    env:
      - name: DB_PASSWORD
        valueFrom:
          secretKeyRef:
            name: app-secret
            key: DB_PASSWORD

-----------------------------------------------------------

2. envFrom
  - All Secret keys → environment variables.

    envFrom:
      - secretRef:
          name: app-secret

-----------------------------------------------------------

3. Volume
  - Secret can also be mounted as files:

          Secret
             ↓
          Volume
             ↓
          /etc/secrets/
             ├── DB_USERNAME
             └── DB_PASSWORD

-------------------------------------------------------------------------------------------------------------------------------------------------------------

(*) ConfigMap vs Secret

|                           | ConfigMap            | Secret              |
| ------------------------- | -------------------- | -----------------   |
| Purpose                   | Non-sensitive config | Sensitive data      |
| Example                   | `LOG_LEVEL=info`     | `DB_PASSWORD=xxx`   |
| Environment variables     | ✅                    | ✅                  |
| Volume mount              | ✅                    | ✅                  |
| Base64 required in `data` | ❌                    | ✅ commonly         |
| Encryption by Base64      | ❌                    | ❌                  |


- ConfigMap is for configuration; Secret is for sensitive configuration.

- Kubernetes Secrets are not automatically equivalent to encrypted secrets at rest. Depending on cluster configuration, Secret data may be stored in etcd
and encryption at rest must be configured/enabled appropriately.

- So in real production environments, you may also see:
    AWS Secrets Manager
    HashiCorp Vault
    External Secrets Operator
    Cloud KMS... integrated with Kubernetes.

-------------------------------------------------------------------------------------------------------------------------------------------------------------

🎯 What you need to remember

    Secret
    │
    ├── Sensitive data
    │
    ├── type: Opaque → generic Secret
    │
    ├── data → commonly Base64 encoded
    │
    ├── Base64 ≠ encryption
    │
    └── Pod can consume it through:
           ├── secretKeyRef
           ├── envFrom
           └── volume
