(*) DNAT (Destination Network Address Translation) 
It rewrites the destination IP address and/or port of an incoming packet. In Kubernetes, kube-proxy programs iptables/IPVS rules that use DNAT to rewrite traffic
destined for a Service (ClusterIP or NodePort) to the IP and port of one of the backend pods.

Before DNAT
The browser sends => Destination: 192.168.49.2:32111

After DNAT
iptables rewrites it to => Destination: 10.244.0.117:80
Now the Linux kernel says: "The destination is now Pod 10.244.0.117:80, so I'll route the packet there."

*******
The Service (ClusterIP) is a virtual abstraction. It doesn't exist as a real network interface / in the real networking path. kube-proxy uses the Service definition to generate iptables
rules, but for NodePort traffic, the packet is ultimately DNAT'd directly to one of the backend endpoints (pods).The real forwarding target is always the EndpointSlice (pods).
*******

"The browser sends traffic to the Node IP and NodePort. The packet reaches the node, where kube-proxy has already installed iptables rules for that
NodePort. The NodePort rule jumps to the Service chain, which uses the Service's EndpointSlice to choose one backend pod. Finally, a DNAT rule 
rewrites the packet's destination from the Node IP and NodePort to the selected pod's IP and target port, and the Linux kernel routes the packet to that pod."
