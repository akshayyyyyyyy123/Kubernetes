* IP TABLES

- iptables is a Linux command-line firewall tool used to control and secure network traffic by defining packet-filtering rules.
- It controls incoming, outgoing and forwarded traffic based on IP addresses, ports and protocols.
- Uses tables, chains, and rules to define how network packets should be handled.
- Performs actions such as ACCEPT, DROP, REJECT, or FORWARD when packets match rules.
- Helps protect servers and networks by allowing trusted traffic and blocking unauthorized access.

It contains rules like: 
                                IF packet matches this condition
                                              ↓
                                        Do this action


                                IF destination = 10.107.210.106
                                              ↓
                                    Forward to another chain

* Core Components of iptables

i) Tables 
ii) Chains
iii) Rules
iv) Targets

- Suppose lets say a packet arrives at -> Destination = 10.107.210.106. Linux says, "I don't have any process listening on this IP." Normally it'd drop the packet.
So Kubernetes has to teach Linux: "Whenever you see this IP, don't drop it. Send it to one of these Pods."... Using iptables.

STEP 01:
- Imagine a packet arrives like this: Destination IP = 10.107.210.106. Linux checks the KUBE-SERVICES chain. It finds, IF destination == 10.107.210.106 then 
Jump to KUBE-SVC-2LGLSIXP4TMEMYBA.
- So KUBE-SERVICES acts like a directory of all Services.

STEP 03: 
- Each Pod gets its own KUBE-SEP chain.
- nginx-pod-1 : 10.244.0.110
- nginx-pod-2 : 10.244.0.109
- kubeproxy creates all these.

STEP 04:
- statistic mode random probability 0.50000000000
- Since you have 2 Pods, kube-proxy is effectively saying: 50% chance of Pod1 and 50% chance of Pod2.
- That's how Kubernetes load-balances between the Pods.
- If you had 4 Pods, you'd see different probabilities and chains to distribute traffic across all four.

"How does a ClusterIP Service send traffic to Pods?"
- "The Service gets a virtual ClusterIP. kube-proxy watches the API server for Services and EndpointSlices, then programs Linux iptables rules. When traffic reaches the ClusterIP, those rules match the Service, choose one of the backend Pod endpoints, perform destination NAT (DNAT) to the selected Pod IP and port, and forward the packet."
