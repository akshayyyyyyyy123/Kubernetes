Kubernetes ServiceAccount

What is a ServiceAccount?
- A ServiceAccount is a Kubernetes identity that allows a pod or application running inside Kubernetes to authenticate to the Kubernetes API or when configured
with the appropriate integration, access external services such as AWS.
- A human uses something like : kubectl → your user identity
- A Pod/application can use   : Pod → ServiceAccount → Kubernetes API

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

Why do we need it?
- Suppose your application running inside a Pod needs to ask Kubernetes, "Give me information about Pods." The application needs an identity to make that 
API request. That's where a ServiceAccount comes in:

                                             Application
                                                  ↓
                                                 Pod
                                                  ↓
                                             ServiceAccount
                                                  ↓
                                             Kubernetes API

- ServiceAccount tells Kubernetes WHO the application is. It doesn't automatically tell Kubernetes WHAT that application is allowed to do. That's where RBAC
comes in.
            ServiceAccount → WHO are you?
            RBAC           → WHAT can you do?

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

Default ServiceAccount
- Every Kubernetes namespace normally has a default ServiceAccount.
- A Pod can use the default ServiceAccount if you don't explicitly specify one.

# kubectl get serviceaccounts
NAME      SECRETS   AGE
default   0         28d

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

How does it work with AWS?
- For example, in EKS, we can use EKS Pod Identity to allow a Kubernetes pod to access AWS services such as S3, without storing AWS access keys inside the pod.

                                    Kubernetes Pod (Runs your application)
                                                   ↓ 
                                    ServiceAccount (Identifies the pod's Kubernetes identity)
                                                   ↓ 
                                    EKS Pod Identity / AWS SDK credentials (Provides temporary AWS credentials)
                                                   ↓  
                                    AWS IAM Role (IAM permissions determine what the pod can do)


- ServiceAccount: Kubernetes identity assigned to a pod.
- IAM Role: Defines what actions are allowed in AWS.
- EKS Pod Identity: Connects the Kubernetes ServiceAccount to an AWS IAM role and supplies temporary credentials.

Creating your own ServiceAccount

apiVersion: v1
kind: ServiceAccount
metadata:
  name: my-app-sa

---

apiVersion: v1
kind: Pod
metadata:
  name: my-app-pod
spec:
  serviceAccountName: my-app-sa

  containers:
    - name: my-app-container
      image: nginx:alpine


# kubectl apply -f sa.yml
serviceaccount/my-app-sa created
pod/my-app-pod created

# kubectl get serviceaccounts                                                                                                                         
NAME        SECRETS   AGE
