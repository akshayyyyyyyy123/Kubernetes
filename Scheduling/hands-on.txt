Step 03 — Test multiple nodeSelector labels

# kubectl label node minikube name=master-node
# kubectl label node minikube-m07 name=worker-node-07
# kubectl label node minikube-m09 name=worker-node-09

example 01: 
pod.yaml

apiVersion: v1
kind: Pod
metadata:
  name: log-pod-5
spec:
  nodeSelector:
    role: logging-role
    name: master-node
  containers:
  - name: log-container
    image: nginx:alpine

kubectl get pods -o wide                                                                                                                            
NAME           READY   STATUS    RESTARTS   AGE     IP             NODE       NOMINATED NODE   READINESS GATES
frontend-pod   0/1     Pending   0          29m     <none>         <none>     <none>           <none>
log-pod-5      1/1     Running   0          4s      10.244.0.202   minikube   <none>           <none>

- This demonstrates role: logging-role AND name: master-node

Example 02: 
pod.yaml

apiVersion: v1
kind: Pod
metadata:
  name: log-pod-test
spec:
  nodeSelector:
    role: logging-role
    name: worker-node-07
  containers:
  - name: log-container
    image: nginx:alpine

kubectl get pods -o wide                                                                                                                            
NAME           READY   STATUS    RESTARTS   AGE     IP             NODE       NOMINATED NODE   READINESS GATES
log-pod-test   0/1     Pending   0          16m   <none>         <none>     <none>           <none>

- The kube-scheduler looks for the node having both role: logging-role AND name: worker-node-07. But we dont have a node satisfying both the conditions.
Hence the pod remain in "PENDING" state.
